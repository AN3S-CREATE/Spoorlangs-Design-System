# Key decisions

Lightweight ADR log. Newest last.

| # | Date | Decision | Rationale | Status |
| --- | --- | --- | --- | --- |
| 1 | 2026-10-08 | Build the deliverable as a Claude **Design System** artifact (https://claude.ai/artifact/7nj8ka81Ne5UvSpfNXk2Uo) kept in files under `project/`, with this folder as the editable mirror. | The user asked for "a Design System from Claude"; the typed artifact is the browsable reference other agents read, and the local copy is what the user edits and can version. | Active |
| 2 | 2026-10-08 | The live site is the only source: `styles-BpVU00Sv.css`, the server-rendered pages, the copy, and the PNG/SVG assets it ships. Nothing is re-tinted, rounded or invented; gaps are written down as gaps. | The type's craft rules ("exact values from real sources") and the user's earlier 360 Vision Events system, which "records only what the site actually uses". | Active |
| 3 | 2026-10-08 | One theme (`dark`). No light theme is authored. | The site declares a single black `:root` palette; a light theme would be invention. Flagged in the brand book's known gaps. | Active |
| 4 | 2026-10-08 | Colour tokens keep the site's own variable names and exact `oklch()` values (leading zeros added); the `color-mix()` recipes become extra 8-digit-hex tokens named by component and role, with the recipe in the usage note. | The page cannot read `color-mix()`; mixing with transparent in oklab is exactly an alpha scale, so the hex8 is exact, and components can then use `var(--token)`. | Active |
| 5 | 2026-10-08 | Fonts ship as real files: Montserrat and Oswald variable latin woff2 from the fontsource packages on jsDelivr (SIL OFL), weights 400–900 and 500–700 as the site requests. | The type's checklist wants the type scale wired to real font files; Google's font host was unreachable from this machine, fontsource serves the same OFL fonts. | Active |
| 6 | 2026-10-08 | Icons: the 14 lucide icons the site renders, copied from `lucide-static@1.52.0` (ISC) as SVG files in `assets/Icons`. | The site uses lucide-react; its minified bundle does not expose the SVGs, so the package is the faithful source. Version pinned, two weeks old at least. | Active |
| 7 | 2026-10-08 | Components are hand-written React 18 function components (`window.Spoorlangs`) whose CSS is the site's own rules copied verbatim; each README says so. | The site's component source is minified and unavailable; the type's references allow hand-written small components when labelled. Verbatim CSS keeps "code is truth". | Active |
| 8 | 2026-10-08 | Previews reference uploaded assets as `/_blob/<id>`; logos, icons and photographs are uploads recorded in `design-system.json`, never inlined. | The type stores non-text assets as uploads in a files-kept system. Blob ids are recorded in `.index/file-inventory.md`. | Active |
| 9 | 2026-10-08 | The build was orchestrated as a multi-agent workflow: 5 inventories → adversarial refuters (exactness, completeness) → corrector → tokens → parallel writers → 3 reviewers → fixer; deterministic validators (`validate-tokens.js`, `assemble-bundle.js`) gate the result. | Ultracode mode was on; exhaustive, verified extraction mattered more than speed. | Active |
| 10 | 2026-10-08 | Two sources with a precedence: the **Spoorlangs Brand Book v1.0** (8 Oct 2026, Canva) governs identity; the **live site** is the exact web implementation. Where they disagree the system records both and lists the discrepancy for Andries Liebenberg (who approves brand changes). Supersedes the "site is the only source" wording of decision 2. | The user supplied the book after the site extraction; it names colours, primary faces, logo rules, scale and voice the site cannot. Choosing silently would misstate the brand. | Active |
| 11 | 2026-10-08 | Colour tokens carry the book's names (`asphalt-black`, `ignition-orange`, `burnt-copper`, `titanium-silver`, `steel-grey`, `white`, `success-green`); the site's semantic variables alias them where the oklch converts exactly to the book hex, and keep their literal oklch otherwise (`card`, `muted`, `muted-foreground`, `border`, `secondary-foreground`). | Both sources describe the same colours; aliases make that explicit and keep the compiled CSS identical for the site's components. | Active |
| 12 | 2026-10-08 | Four font files ship: Bebas Neue and Inter (book primaries) plus Oswald and Montserrat (book alternates, what the site loads). Family keys `display`/`sans` keep the site's values so component CSS renders exactly; `brand-display`/`brand-sans` carry the primaries. | The site's CSS depends on `--font-display`/`--font-sans`; renaming them would change how every component renders. | Active |
| 13 | 2026-10-08 | Logos: the approved 14 Sep 2026 set (12 usable PNGs) replaces the site's two files as the Logos group; Monochrome Black is not uploaded (the book holds it back for a misspelling); the WhatsApp avatar and the site's favicon/apple-touch-icon/Facebook cover are kept as derived files. The hero loop MP4 and its GIF form a Motion group. | The book names the approved set as the logo source of truth; shipping a held-back file invites misuse. | Active |
| 14 | 2026-10-08 | One intentional component addition beyond the site's families: `IgnitionRule` (the book's 96 × 5 px orange rule under headings). No other "usual" components are added. | The type's craft rules allow additions only when listed with a reason; this one is defined by a real source. | Active |
| 15 | 2026-10-08 | Launch templates become a fifth asset group, **Templates**: 15 PNGs exported from the brand's own Canva designs ("Launch Editable Extra", "WA Extra"), each recorded with its Canva design id and edit link, and each given a compliance verdict against the Brand Book (approved-pattern / fix-before-reuse / do-not-reuse) rather than silently stored. The September concept renders on the owner's disk are excluded as superseded. | The book's page 27 names these templates as part of the brand; several break its hard rules (AI-rendered wordmarks, fake stars, amber text), and a design system that stored them without saying so would propagate the breaches. | Active |
